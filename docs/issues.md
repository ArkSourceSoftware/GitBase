# Issues Documentation

## Overview

Issues provide a way to track bugs, feature requests, improvements, and other tasks within a GitBase repository.

Issues help teams organise work, discuss changes, and keep track of repository activity. Each issue can include a title, description, labels, assignees, comments, and status tracking.

## Creating an Issue

### From the Web Interface

1. Navigate to your repository's **Issues** tab.
2. Click **New Issue**.
3. Enter a title describing the issue.
4. Add a detailed description explaining the problem, request, or task.
5. Add labels, assign users, or configure additional options as required.
6. Click **Create Issue**.

Once created, the issue will be available for discussion and tracking by repository contributors.

## Managing Issues

Issues can be managed throughout their lifecycle by repository contributors with the required permissions.

Common issue management actions include:

- Editing the issue title or description
- Adding labels to categorise and organise issues
- Assigning issues to users responsible for resolving them
- Adding comments and discussion
- Closing completed or resolved issues
- Reopening previously closed issues

## Issue Comments

Issue comments allow contributors to discuss the issue, provide additional information, and share updates.

Comments can be used to:

- Provide additional details about a problem
- Discuss possible solutions
- Ask questions
- Provide status updates
- Link related commits or pull requests

## Labels

Labels help organise and categorise issues within a repository.

Examples of common labels include:

- **Bug** - Reports of unexpected behaviour or errors
- **Feature** - Requests for new functionality
- **Enhancement** - Improvements to existing functionality
- **Documentation** - Updates or improvements to documentation
- **Question** - Requests for help or clarification

Repositories can create and manage custom labels to match their workflow.

## Assigning Issues

Issues can be assigned to one or more users to indicate who is responsible for investigating or completing the work.

Assigned users can use the issue list to track tasks that require their attention.

## Linking Issues and Pull Requests

Issues can be linked with pull requests to associate code changes with the work being completed.

Linking issues and pull requests helps provide context by showing:

- Which changes address a specific issue
- The progress of related work
- The history of discussions and solutions

## Closing Issues

When an issue has been resolved, it can be closed by users with the required permissions.

Closed issues remain available for reference and can be reopened if additional work is required.
